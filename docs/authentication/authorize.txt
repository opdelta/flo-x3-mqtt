Synthetic example. All credentials and flow identifiers are placeholders.
Public tenant/client identifiers are defined in flo_client/api.py.

POST https://auth.pingone.ca/<tenant-id>/as/authorize
Content-Type: application/x-www-form-urlencoded

client_id=<public-client-id>
response_mode=pi.flow
response_type=code
scope=eMobility:all
code_challenge_method=S256
code_challenge=<generated-pkce-challenge>

The fields above are form-encoded in one request body.
Generate a new PKCE verifier/challenge pair for each full authentication flow.

Example response fields used by the bridge:

{
  "status": "USERNAME_PASSWORD_REQUIRED",
  "_links": {
    "usernamePassword.check": {
      "href": "<username-password-check-url>"
    }
  }
}

Follow the returned link rather than constructing a flow URL.
